# v2.4 优化项 — 实战发现的问题

来源：用 pt 管理「智能助眠枕头」项目时发现的不足

## P0 — 必须做

### 1. 文档管理与同步 (pt docs)
**问题**：pt 只管任务状态，不管项目文档。实际硬件项目中，每个任务都有对应的文档产出（调研报告、设计方案、评审记录、测试报告等）。目前文档散落在 Notion/GitHub/本地，pt 完全不知道。

**需求**：
- `pt note <task_id>` — 给任务附加笔记/文档内容（当前只支持 --note 短备注）
- `pt docs <task_id>` — 查看任务关联的文档/交付物状态
- `pt docs --sync` — 将项目文档同步到 GitHub 仓库
- 任务的 deliverables 字段应该能关联到实际文件路径

### 2. 任务备注太弱
**问题**：`pt done task --note "xxx"` 只能写一行短文本。实际项目中，完成一个任务时需要记录大量信息（决策结论、关键数据、遗留问题等）。

**需求**：
- 支持多行备注或关联 markdown 文件
- `pt note <task_id> --file path/to/doc.md` — 关联外部文档
- `pt note <task_id>` — 交互式编辑（打开 $EDITOR）

### 3. 项目关联 Git 仓库
**问题**：pt 项目和 Git 仓库是割裂的。项目文件在 project-tracker/projects/ 下，但实际项目代码/文档在另一个仓库。

**需求**：
- `pt init` 时可指定 `--repo <path>` 关联 Git 仓库
- `pt sync` — 将项目状态/文档同步到关联仓库
- 项目 YAML 中增加 `repo` 字段

## P1 — 应该做

### 4. guide 问题模板与流程解耦
**问题**：guide_questions.yaml 的阶段 ID 是按度信流程写的（REQ/FEAS/INIT...），generic 流程用不同的 ID（CONCEPT/DESIGN/PROTO...），需要手动加别名映射。

**需求**：
- 问题模板应该按「问题类型」组织，不按阶段 ID
- 或者每个流程定义自带问题映射

### 5. 任务工时默认值不合理
**问题**：所有任务默认 3 天，导致 generic 流程总工期 45 天，不够真实。

**需求**：
- 流程定义中每个任务应该有合理的默认工时
- `pt estimate --batch` — 批量设置工时
- 或者按任务类型自动推断（设计类 5-10 天，评审类 1-2 天，采购类 7-14 天）

### 6. 决策记录 (pt decide)
**问题**：项目推进中有大量决策点（选型、定价、方案选择等），目前只能用 --note 记录，没有结构化的决策追踪。

**需求**：
- `pt decide <task_id> --question "Q1:目标用户" --choice "A:都市精英"` — 记录决策
- `pt decisions` — 查看所有决策记录
- 决策可以触发后续任务的参数变化

## P2 — 可以后做

### 7. 项目模板自定义
**问题**：目前只有 duxin/generic/minimal 三个流程。用户应该能快速创建自己的流程模板。

### 8. 项目仪表盘 (pt dashboard)
**问题**：status 命令信息密度高但不够直观。需要一个更紧凑的仪表盘视图。

### 9. 多项目关联
**问题**：助眠枕头项目可能有子项目（硬件子项目、固件子项目、APP子项目），目前不支持项目间的父子关系。
